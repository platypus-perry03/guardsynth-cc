# 세 리뷰어 대응: 통제 시나리오 실행 및 서론 보완

## 이번 실행의 결론

연속 CoC의 의무와 해제 근거를 연결하여 모순과 근거 부족을 구분하고 문제 위치를 추적하는 방식은 통제된 구조화 시나리오에서 실행 가능했다. 기존 구현의 한계도 확인했으며 이를 보완한 별도 UPPAAL 모델은 같은 시나리오의 판정과 문제 위치·의무·사유를 재현했다. 이 결과는 자연 발생 오류 정확도, 독립 외부 검증, 범용 자동 추출 성능을 입증하지 않는다.

## 고정된 시험 범위

6개 상황(보행자·자전거·선행차·교차 차량·버스·장애물), 8개 변형, 중간 사건 0/2/6개를 조합한 144개 사례다. 의미상 모순 72개, 일관된 사례 36개, 근거 부족 36개다. 같은 의미 틀의 변형을 독립 자연 표본처럼 세지 않으며 모집단 신뢰구간을 부여하지 않는다. 문장과 구조화 프레임은 함께 작성했고, 기대 판정은 최초 검사 실행 전에 고정했다. 사람 정답이나 외부 개발 미사용 시험이라고 부르지 않는다.

## 최초 실행 결과 — 보존됨

| 검사 경로 | 의미 판정 일치 | 확정 오류 최초 위치 일치 |
|---|---:|---:|
| 기존 이전 요구 유지 검사 | 96/144 | 54/72 |
| 기존 현재 사건 검사 | 72/144 | 36/72 |
| 이전 1개 + 현재 사건 | 84/144 | 42/72 |
| 이전 3개 + 현재 사건 | 90/144 | 48/72 |
| 이전 5개 + 현재 사건 | 90/144 | 48/72 |
| 별도 조건 ID 기반 단순 FSM | 144/144 | 72/72 |
| 기존 원문 자동 추출 + 검사 | 36/144 | 0/72 |
| 기존 UPPAAL 모델 | 96/144 | 54/72 |

기존 검사기에서 확정 오류로 잘못 표시한 정상 사례는 0/36이지만, 정상 36개 중 30개를 UNKNOWN으로 남겼다. 따라서 오탐 0만으로 정상 판단 성능이 좋다고 해석하면 안 된다. 기존 자동 경로는 전 사례 UNKNOWN이었다. 그중 기대 미상 36개와 일치한 것은 의미 추출이 성공했다는 증거가 아니다.

원문→프레임 투영은 조건 ID에 맞는 증거만 기존 release 필드에 넣는 작성 자료 변환이다. 원문에서 자동으로 의미를 이해한 결과가 아니다. 이전 N 비교는 동일 검사기의 창 크기 ablation이며 별도 경쟁 알고리즘이 아니다. FSM은 별도 구현했지만 같은 설계자가 만든 의미 명세를 따르므로 독립 정답은 아니다. FSM이 잘 동작하므로 복잡한 모델 검사가 탐지 정확도에서 우월하다고 주장하지 않는다.

## 실패 원인과 보완 재시험

- 기존 의미 판정 불일치 48건: 복수 의무 일부 해제 18건, 복수 의무 모두 해제 18건, 중간 대기 이후 정상 해제 12건. 앞의 36건은 단일 활성 의무와 증거 투영의 범위 한계, 뒤의 12건은 기다리는 동안의 미상도 전체 판정에 남기는 누적 정책이다.
- 기존 Python/UPPAAL은 판정·오류 종류·최초 위반 위치가 144건 모두 같았다. 미상 사유 목록은 24건 달랐다. 최초 반례 출력은 사건열 끝까지 진행하지 않을 수 있어 뒤의 사유가 빠졌다. 원래 XML의 종료 상태를 별도 질의하자 미상 사유도 144건 모두 Python과 같았다. 기존 파서는 수정하지 않았으며 최초 24건 차이는 보존했다.
- 별도 UPPAAL 보완 모델에서는 각 의무의 조건 ID와 증거를 연결하고, 기다리는 동안의 미상과 종료 근거 없이 출발한 경우를 구분했다. 같은 cases.json의 정답 변경 없이 판정 144/144, 모순 최초 위치 72/72, 문제 위치·의무·사유 각각 108/108이었다.
- 보완 모델은 실패 분석 후 작성한 동일 사례 재시험이다. 기존 결과를 덮어쓰거나 새 독립 평가로 표현하지 않는다. 사건 순서와 조건의 일관성을 검사하며 정량적인 제한 시간·차량 동역학은 모델링하지 않았다. 기존 반응 시간 분석은 별도 보조 근거다.

## 사례로 설명할 핵심

A로 정지한 뒤 B를 근거로 출발할 때, A의 종료가 거짓이면 모순이고 알려지지 않았으면 해제 근거 부족이다. B가 참이거나 다른 대상의 조건이 해제되더라도 A를 해제하지 않는다. 실제 검증 기록은 원문 사건 ID→의무와 종료 조건→근거 구절→문제 행동→판정/위반 ID로 연결된다. 비교 HTML의 접힌 상세 항목에서 확인할 수 있다. 단순한 원문 구절 링크는 의미 추출 정확도를 입증하지 않는다.

## 서론 및 검증

서론에는 CoC 생성·작성 과정의 누락 가능성, 보행자 정지→녹색 신호 출발 예시, 모순/근거 부족/정상 해제의 구분, UPPAAL을 통한 시간 순서·조건 검증 동기를 반영했다. 본문 전체가 새 모델·수치와 정렬된 제출본은 아직 아니다. 미리보기 PDF는 서론 수정 확인용이다.

기존 검사 시험은 동일 실제 실행 환경에서 166개 통과, 추가 파이프라인 시험 36개 통과했다. 원고 검사는 25개 중 24개 통과·1개 원본 보존 fixture 부재로 skip. 제한 환경의 첫 기존 시험 실행은 검토 패킷 접근 1건 실패와 verifyta 라이선스 1건 skip을 보였으며, 실제 실험과 같은 승인된 환경에서는 모두 통과했다. 코드를 변경해 이를 숨기지 않았다.

검토 에이전트가 새 파이프라인과 보완 모델을 읽고 실제 사례·정답·원문 구절·입력 해시·모델·solver 로그를 대조했으며 중요한 결함을 보고하지 않았다. 이는 코드 검토이며 연구의 독립 사람 정답 평가가 아니다.
