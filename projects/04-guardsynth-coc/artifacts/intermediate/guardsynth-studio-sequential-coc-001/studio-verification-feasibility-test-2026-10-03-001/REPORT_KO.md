- project_id: `guardsynth-coc`
- subproject_id: `guardsynth-studio-sequential-coc`
- 기준일: 2026-10-03
- 성격: 합성 입력의 현행 검증기 성능 탐색. 신규 entity/관계·인과 계약은 미구현.
- 유료 모델 호출: 0회

## 측정 방법

현행 `SEQ_CHECK` CPU child에 동일 입력을 사례별 2회 실행했다. 기본 제한인 벽시간 30초, CPU 30초, 주소 공간 1GiB를 유지했다. 각 측정은 별도 부모 프로세스를 사용했다. wall에는 child 실행, 결과 읽기/파싱과 결과 크기 측정을 위한 재직렬화가 포함된다. RSS는 Linux resource.getrusage의 peak이며, 부모 RSS에는 측정용 재직렬화도 포함된다. 실제 장기 실행 Studio 서버의 메모리 측정값이 아니다.

모든 조건은 합성 REQUIRE HOLD이며, 시점당 최대 16후보를 통해 조건이 누적된다. 64조건 사례는 4개 묶음을 순환한다. varying 사례는 고정 seed로 TRUE/FALSE를 바꾸어 캐시가 어려운 입력을 만든다. 실제 영상 품질, 정량 안전성, 신규 관계 모델의 정확도 또는 최악 실행시간 보증은 평가하지 않았다.

## 해석과 설계 반영

- 작은 Bool 계약은 이 호스트에서 짧게 끝났으나, 2회 실행만으로 p95/p99나 최악 시간을 주장하지 않는다.
- 200시점 반복 상태 완료는 캐시 재사용의 영향을 받는다. 상태 변화 200시점은 두 번 모두 timeout이므로 반복 사례를 범위 전체의 성능 근거로 쓰지 않는다.
- 현행 기본 검사는 각 모델에 기본 질의 2개와 조건별 상세 질의를 실행한다. 상세 진단 전수 실행을 기본에서 분리하는 설계가 필요하다.
- 반복 200시점 결과 JSON은 약 74MiB다. 같은 Core/SMT 자료의 중복 반환을 immutable 참조·요약으로 바꾸는 설계가 필요하다.
- 1차 제안은 현재 검사 통상 2초 목표/3초 작업 한도, 구간 전체 EBLC·검증·CNL 30초 총 예산이다. 이것은 구현·검증된 보장이 아니다.
- 미확인, 가정하의 충돌, 확정 입력의 모순, timeout을 구별하고 전체 완전성/실제 인과 효과/무제한 동역학 검증은 1차에서 제외한다.
