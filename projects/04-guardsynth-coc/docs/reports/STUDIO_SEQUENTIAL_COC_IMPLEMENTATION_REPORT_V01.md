## 현재 구현

화면은 **CoC 생성 → 제약 생성 → EBLC 생성 → 검증 → CNL 생성** 다섯 단계다.
CoC와 제약 생성에는 바로 이전·현재 최대 두 프레임과 해당 시점까지의 CAN을 보내고,
더 오래된 조건은 최대 64개 정의·상태 요약으로 전달한다. 전체 과거 영상이나 전체 과거 SMT를 다시 넣지 않는다.
EBLC·검증·CNL에는 모델 호출이 없다. 원래 저장된 단순 형식과 API는 호환성을 유지한다.

CoC에는 실제 관찰 행동, 대상 entity, 방향을 가진 관계, 행동 대상, 근거와 미확인을 생성한다.
제약은 신호·교통 통제, 다른 차량, 보행자·자전거, 도로 구조, 공사·장애물, 노면, 시야의 7개 상위 클래스로 나눈다.
원인 대상과 행동 적용 영역을 구분하고, 불변 정의와 현재 사실값을 분리한다.
활성·유지·해제, 선행 조건, 이후 장면에서 확인할 기대 후행 조건을 표현한다.
녹색 신호를 실제 진입 증거나 진입 의무로 바꾸지 않으며, 공간 점유와 경로 충돌도 구분한다.
현재 영상에서 확인하지 못한 조건은 UNKNOWN으로 남긴다. CAN만으로 신호·타차 관계·실제 영역 진입을 증명하지 않는다.

기존 공유 Core IR와 Z3로 즉시 이전 상태 및 현재 장면의 질적 일관성을 검사한다.
같은 종류의 새 대상이라는 이유만으로 이전 위험을 해제하지 않는다.
활성 조건은 관찰 충돌·미확인을 거쳐도 확인된 해제 전까지 유지한다.
후행 조건은 이전에 실제로 수행된 해당 행동과 연결하여 다음 장면에서 확인한다.
규칙 출처 검토 상태는 논리 검증 상태와 별도로 표시한다.
이전 장면의 수정이나 늦은 생성은 관련 결과를 무효화하여 다시 검증하도록 한다.
질의당 시간 한도와 작업당 30초·1GiB 한도를 유지한다. 제한 때문에 확정되지 않은 결과를 통과로 바꾸지 않는다.

검토 UI는 원문과 수정본, 수정 없는 수용 체크를 구분한다.
상세 정형 항목은 접혀 있고, 배열 항목 추가·삭제 및 모델 제안으로 되돌리기를 지원한다.
반례에는 원문의 시점·항목·값·근거를 표시하고 클릭하면 해당 수정 칸으로 이동한다.
방향 관계나 사실값을 수정한 뒤 EBLC·검증·CNL을 다시 실행할 수 있다.

최초 모델 생성 쌍의 결과는 생성 ID·원문·당시 입력 요약·검증기 서명에 묶어 보존한다.
사람이 수정한 뒤의 결과와 최초 결과를 따로 집계하며, 사람의 수정이 포함된 이전 문맥을 사용한 생성도 구분한다.
과거 CoC의 문장 수정만 있었더라도 보수적으로 사람 개입으로 분류할 수 있다. 논리 통과 여부는 별도로 남긴다.
아직 검사되지 않은 생성 쌍과 생성 실패도 표시하므로 통과한 결과만 분모에 넣지 않는다.
품질 화면 GET은 저장된 결과만 읽으며 DB 트랜잭션 안에서 SMT를 실행하지 않는다.

이전 장면에서 넘어온 제약, 설명, 관찰 행동은 검증 및 CNL·내보내기에도 유지한다.
독립 리뷰에서 발견한 대상 동일성, 활성 상태 지속, 사람 개입 출처, 진입 대상 타입,
수정 항목 추가/삭제, 정확한 반례 값·경로 및 carried CNL 문제를 회귀 시험으로 확인했다.

## 기존 서버 반영

작업 시작 파일 SHA와 비교해 검증한 변경 파일 14개만 기존 작업공간에 적용했다.
DB를 온라인 백업하고 같은 run ID·인증·45453 포트로 재시작했다.
517개 시점·594개 revision과 DB 전체 논리 내용 SHA 및 인증 파일을 보존했다.
누적 호출 355회, 상한 400회, 남은 45회를 유지했다.
상세 구조화 결과의 잘림을 줄이기 위해 출력 토큰 한도를 2048에서 8192로 늘렸다.
새 코드를 제공하는 HTTP 정적 파일의 SHA가 검증한 파일과 일치한다.
저장소 파일명 검사에는 기존 10개 위반이 남아 있으며 이번 변경으로 추가한 위반은 없다.
