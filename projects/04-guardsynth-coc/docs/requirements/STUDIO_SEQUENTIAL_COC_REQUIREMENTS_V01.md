# Studio Sequential CoC 요구사항 v0.1

- project_id: guardsynth-coc
- subproject_id: guardsynth-studio-sequential-coc
- parent: guardsynth-studio
- 요청 근거: 사용자가 요구사항·설계 이후 스튜디오에 직접 구현하도록 요청함 (2026-10-02).
- 상태: 2026-10-04 생성·검증 연결 요구사항 반영. 구현 기준. 새로운 연구 주장이나 학습용 데이터 승인 규정을 대체하지 않는다.

## 목적과 범위

녹화된 영상과 t0 이전 CAN으로 실제 관찰 행동의 설명 CoC를 VLM이 생성한다.
그 CoC를 보존한 채 같은 인과적 입력에서 VLM이 제약 후보를 별도로 만든다.
후보를 결정적으로 EBLC Core IR로 변환하고 개별 장면과 상태를 이어받는 인접 장면을 검사한다.
완성된 실제 운전자 의도나 사고 부재를 안전성 증명으로 간주하지 않는다.

## 기능 요구사항

1. 새 흐름은 기존 추천 행동 CoC와 별도 구성요소로 저장한다. 기존 승인·DB·호출 상한을 유지한다.
2. 생성은 사용자가 버튼을 누를 때만 한다. 기본 CoC와 제약 생성 각각 1회 사용하며 검사에는 VLM 호출이 없다.
3. CoC에는 관찰 사실, 실제 관찰 행동 목록, 설명 본문, 미확인을 둔다. 출발 START, 정지 행동 STOP,
   주행 지속 CONTINUE, 공간 진입 ENTER, 정지 유지 HOLD를 구분한다. 동시에 관찰 가능한 행동은 복수로 둔다.
   정당성은 설명 가설이지 정답 승인이 아니다. 미래 영상으로 행동 정답을 확정하는 기능은 이번 구현에서 제외한다.
4. 기본 CoC 원문과 작성자 수정본을 나란히 표시한다. 수정이 없으면 수용 체크를 해야 검토 확인이 된다.
5. 구조화 CoC는 장면 대상(entity), 방향 있는 관계, 자차 관찰 행동과 적용 영역을 포함한다.
   제약은 신호·차량·취약 도로 사용자·도로 구조·공사/장애물·노면·가시성의 7개 상위 클래스로 나눈다.
   원인 대상과 행동 적용 대상을 분리하고 FORBID/REQUIRE/ALLOW, 활성·해제 원자 조건,
   행동 선행 조건 및 기대 후행 조건을 생성한다. 불변 조건 정의와 현재 관찰 사실은 별도 저장한다.
6. 제공하지 않은 규칙 원문을 만들지 않는다. 규칙 원문 부재는 법적 출처 검토 상태로 별도 표시한다.
   논리적으로 모순 없는 후보라도 법적 정당성을 승인한 것으로 표시하지 않는다.
7. 동일 조건 ID의 정의는 변경하지 않는다. 이전 대상과 동일한지 불확실하면 연결을 확정하지 않는다.
   제공된 entity·현재/이전 인과적 프레임·CAN 증거 참조만 허용하며 시각 관찰은 여전히 모델 주장이다.
8. 검사 강도는 바로 이전과 현재 장면이다. 더 오래된 장면은 최대 64개 조건의 상태 요약만 넘긴다.
   이전 자료가 없으면 현재 시점에서 부분 시작하고, 이전 자료가 뒤늦게 생기거나 바뀌면 결과를
   무효화하고 다시 검사한다. UNKNOWN이나 대상이 안 보인다는 사실만으로 ACTIVE를 해제하지 않는다.
   해제 원자의 현재 근거가 필요하다. 미래 기대 조건은 현재 참인 사실로 강제하지 않는다.
9. 모순·근거 부족·지원하지 않는 검사·규칙 출처 검토를 구분한다. 빈 제약이나 부분 검사에 PASS를 주지 않는다.
   반례는 해당 원문·근거·시점·수정 항목을 제공하고 사람이 수정한다. 생성 원문은 변경하지 않는다.
   최초 생성 CoC/제약 쌍의 고정 검증 성적은 사람의 수정·승인과 분리하여 보존한다.
   누락/UNKNOWN/검사 미지원도 전체 평가 분모에 포함한다. 수정 후 결과는 별도 표시한다.
10. 결과에 실제 관찰한 시점만 사용한다. 각 조건의 위반 질의와 Core IR/SMT 결과를 추적할 수 있어야 한다.
11. 검사 및 JSON 다운로드는 장면 revision, 승인 상태, 규칙 revision, 영상 권한을 스냅샷으로 묶는다.
    수정이나 권한 철회가 발생하면 이전 검사 결과를 최신 통과 결과로 표시하거나 내려받지 않는다.
12. 내보내기는 DRAFT 연구 검토용으로 기본 CoC, 제약 자연어, 결합 문장과 검사 결과를 보존한다.
    training_eligible=false이며 기존 학습 승인 흐름을 우회하지 않는다.

## 수용 검사

- TRUE → 생략 → UNKNOWN → ENTER: 활성 진입 금지 조건 유지 및 모순 검출.
- TRUE → 근거 없는 FALSE: 해제 금지 및 확인 필요; 근거 있는 FALSE → ENTER: 해당 금지와의 모순 없음.
- 상충 REQUIRE/FORBID: 같은 지점의 규칙 모순을 보고하고 다른 시점 검사에 전파하지 않음.
- ID 의미 변경, 해제 근거 없음, 미래 frame/CAN 참조, 빈 후보, 검사 미지원, 수정 뒤 오래된 검사: 통과 금지. 원문 규칙 부재는 별도 법적 검토 상태.
- 브라우저에서 두 생성 버튼, 수정/수용, 후보 카드, 인접 결과 표, 다운로드를 실제 API로 수행.

## 연구 연결과 한계

현 연구계획 v2.4의 P0 원본 CoC / P1 자연어 제약 / P2 EBLC→CNL 비교에 필요한 원자료를 보존한다.
이번 연결 구현은 학습·시각 인식 정확도 인증을 실행하지 않는다. 생성 초안의 정형 검증 품질과 인간 수정 후 결과는 따로 산출한다. 규칙 목록 대비 누락만 찾을 수 있고
목록 자체의 완전성, 가려진 객체 부재, 충돌 없는 실제 운전은 증명하지 않는다.
Alpamayo의 원인 근거와 행동 표적의 시간 분리 및 BDD-X의 행동/설명 분리를 참고한다:
[Alpamayo §4](https://arxiv.org/html/2511.00088v2), [BDD-X](https://arxiv.org/abs/1807.11546).

## 검증 결과 표시 보완 (2026-10-04)

- 검증 스냅샷에 CoC·제약이 없는 시점은 작성 대기로 표시한다. 이어받은 제약을 보존하되 관찰 행동의 검사가 완료됐다고 표시하지 않는다.
- 설명이 있어도 관찰 행동이 비면 행동 입력 필요로 안내하며, 검토 승인 여부와 구분한다. 기존 형식에서도 실제 행동, 조건 확인 상태, 적용 상황과 관찰 근거를 수정할 수 있어야 한다.
- 규칙 원문·출처 부재는 공통 출처 검토 안내 한 곳에 표시한다. 논리 일치와 법적 출처 승인을 분리하고 원본 상태 코드는 보존한다.
- 같은 작성 상태와 같은 검사 문제는 연속 구간으로 묶는다. 관찰 행동, 조건 상태, 영향 제약 또는 반례가 달라지면 별도 구간으로 남긴다.
- 인접 두 시점의 입력과 검토가 준비되지 않은 쌍은 작성·검토 대기로 표시한다. 대기 중이어도 보고된 규칙 모순은 숨기지 않는다.
- 현재 시점은 누락된 입력과 해당 제약의 구체적인 확인 항목을 표시하고 수정 위치로 연결한다. 미작성 시점을 작성 후 품질 평가의 분모에 넣지 않으며 모델 최초 제안의 원본 평가는 변경하지 않는다.
