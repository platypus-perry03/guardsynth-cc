## 1. 목적과 완료 기준

실제 영상을 사람이 검토하면서 VLM의 상황 이해·행동 선택 학습용 CoC와 제약 강화 CoC를 만드는 웹도구다.
LLM/VLM이 제안하고 사람이 수정·승인한다. EBLC는 구조화, 제한된 논리 검증, 자연어 생성 및 행동 검사에 사용한다.
영상에서 법규나 실제 운전자 의도를 자동 인증하는 도구가 아니다.

첫 버전은 영상 하나에서 두 개 이상의 판단 시점에 대해 CoC 승인 → 제약 승인 → EBLC 검사 →
자연어 제약 결합 → 승인된 행동 레이블과 함께 JSONL 내보내기를 완료해야 한다.
새로고침·서버 재시작 후에도 복구되어야 한다. 실제 모델 호출과 mock을 구분하고 mock만으로 연동 완료를 주장하지 않는다.

## 2. 사용자 흐름

1. 권한 있는 영상을 업로드하고 프레임 추출 간격을 선택한다. 실제 시간 정보를 보존한다.
2. 전체 영상을 시간순으로 탐색한다. 스트립에는 최대 **7개** 프레임을 표시한다.
3. 다음은 한 프레임 이동: 맨 왼쪽이 빠지고 오른쪽에 새 프레임이 추가된다. 이전은 반대다.
4. 현재 판단 시점 t0를 명시한다. 기본 화면에서 오른쪽 끝이 t0이고 나머지는 과거다.
5. VLM이 t0까지의 영상으로 관찰·관계·불확실성·행동 근거를 포함한 CoC 초안을 생성한다.
6. 사람이 CoC를 수정·승인하면 모델이 영상, 승인된 CoC, 명시된 규칙 근거로 제약을 제안한다.
7. 사람이 제약을 승인하면 지원하는 계약으로 변환하여 EBLC/Core/SMT 검사를 실행한다.
8. 검사 통과 계약의 필드에서 결정적 renderer로 자연어 제약을 생성하고 원본과 차이를 표시한다.
9. 사람이 결합 CoC와 행동 레이블을 확인한다. 복수 적절 행동을 허용한다.
10. 승인·검증·분리 상태를 확인하여 학습 데이터 또는 보류 초안을 별도로 내보낸다.

7개는 표시 한도이지 검토 단위나 독립 장면 수가 아니다. 영상 시작에서 부족한 프레임을 복제하지 않는다.
각 시점을 선택하면 그 시점의 저장 항목을 연다. 모든 추출 시점은 항목을 가질 수 있으나 업로드 즉시
무제한 모델 호출하지 않는다. 선택 시점/구간에 대해 생성하며 추출 간격과 모델 입력 수를 별도 기록한다.
첫 시점부터 마지막 추출 시점까지 빠짐없이 선택할 수 있어야 한다. 처음에는 현재 시점까지의
1–7개를 표시하고, 양 끝에서는 범위를 벗어난 이동을 막는다. 미래 시점을 탐색한 뒤 이전 시점으로
돌아와도 모델 대화 이력·캐시·이전 생성물에서 미래 관찰을 가져오지 않는다.

## 3. 기능 요구사항

### GS-01 영상·대상·영역

- 영상 ID, 원본 해시, 출처/사용권한, 실제 타임스탬프, 추출 설정을 저장한다. 고정 FPS를 임의 가정하지 않는다.
- 손상·미지원 영상, 공개된 용량/길이 한도를 넘는 파일은 이유와 함께 거부한다.
- 대상·영역은 읽을 수 있는 이름과 프레임 근거로 연결한다. 필요하면 점/폴리곤을 수정·완전 삭제한다.
- 픽셀 폴리곤을 실제 거리나 차량 궤적으로 간주하지 않는다. 진행 의도를 임의 확정하지 않는다.

### GS-02 CoC·행동 제안 및 승인

- 모델/프롬프트 버전, 실제 입력, 원출력, 사람 수정과 승인 이력을 보존한다.
- 관찰 사실, 추론/가정, 미확인 정보와 제안 행동을 분리한다.
- 전 시점 초안의 재사용은 제안일 뿐 새 시점의 승인이 아니다. 변경 없는 구간은 변경 내용과 대상 시점
  목록을 제시한 후 사람이 명시적으로 일괄 승인할 수 있다.
- 행동은 적절/부적절/판단 불가/해당 없음을 구분한다. 복수 적절 행동을 허용하고 단일 정답을 강제하지 않는다.
- 주행 중 속도 유지와 정지 유지 등 선택지 의미를 예제로 안내한다. 해당 없음의 불필요한 메모를 강제하지 않는다.
- 제약으로부터 만든 행동 레이블을 독립 정답이라고 주장하지 않는다. 작성자 역할과 제약 노출을 기록한다.
- 행동 레이블은 CoC 본문·모델 제안·계약의 허용 행동과 별도 필드 및 승인 버전으로 저장한다.
  계약이 허용한 행동을 자동 승인 레이블로 채우지 않는다.

### GS-03 제약 제안

- 대상, 영역, 적용 조건, 금지/요구 행동, 해제 조건, 시간 범위, 관찰 근거, 규칙 출처,
  가정, 미확인 사항, 지원 프로파일과 승인 상태를 구조화한다.
- 규칙 출처를 외부 근거/연구용 정책/미검증 모델 제안으로 구분한다. CoC는 사실/법규 인증이 아니다.
- 영상으로 알 수 없는 대기시간·법규·국가를 임의 입력하지 않는다. 추천 정책을 법규로 표시하지 않는다.
- TRUE/FALSE/UNKNOWN/CONFLICT와 미적용을 구분한다. 미확인을 거짓으로 바꾸지 않는다.
  통제가 화면에 보이지 않음을 전역적 부재로 확대하지 않는다.
- 기존 proposal 스키마의 `source_claim_refs`/`source_record_refs`, `required_predicate_refs`,
  `applicability`, `binding_status`, `reason_codes`를 보존하고 실제 출처의 버전·위치와 연결한다.
  스키마 통과나 출처 ID의 존재만으로 근거가 확인된 것은 아니다. 사람이 출처 내용과 해당 시점의
  대상·영역 결합을 확인해야 하며, 미해결 결합은 승인된 장면 적용 제약으로 승격하지 않는다.
  `PROPOSED` 등 기존 verdict와 사람의 승인·거절·보류 기록은 별도로 관리한다.

### GS-04 EBLC 작업 공간

- 기본은 쉬운 한글 규칙·근거·승인 상태, 고급 패널은 EBLC/Core 원문 및 검사 상세다.
- MVP는 진입 금지·보류·해제의 제한 프로파일부터 지원한다. 시간 기반 해제는 시간 근거와 프로파일이 있을 때만 지원한다.
- 기존 `eblc-action-contract-v0.1`의 행동은 `DEFER_ENTRY`/`ENTER_ZONE`이며, 모든 의무의
  유효한 FALSE 근거가 있어야 진입을 허용한다. 허용은 진입 강제가 아니며, 보류는 급제동 명령이 아니다.
  UNKNOWN/CONFLICT/무효 근거는 해제가 아니다. 초기 활성 상태와 시점별 근거 유효성을 명시하고,
  모르는 초기 상태나 미래 상태를 솔버 witness에서 관찰 사실로 가져오지 않는다.
  현재 horizon은 2–32개의 추상 판단 단계이고 의무는 1–16개다. 단계 수를 초 단위 대기시간이나
  화면의 7프레임으로 간주하지 않는다. 다른 행동 레이블의 계약 대응은 지원 여부를 별도 표시한다.
- 미지원 제약은 초안 보관하며 임의 근사 후 검증 통과로 표시하지 않는다.
- 고급 명세 수정 시 새 버전을 만들고 파싱·타입 검사부터 다시 수행한다. 의존 검증/CNL 승인을 무효화한다.
- 일관성, 비공허 적용/해제, 경계, 금지 행동 예제를 질의별 기대값/실제값과 함께 기록한다.
  금지 행동에 대한 UNSAT는 성공일 수 있으며 단순 SAT가 모든 검사 통과를 의미하지 않는다.
- UNKNOWN/timeout/오류/미실행은 통과가 아니다. 재현 입력과 사람이 읽는 이유를 남긴다.
- 기본 action-contract lowering은 `base_consistency` 질의만 만든다. Studio의 장면별 검사에는
  승인된 관찰 바인딩과 적용/해제·행동 질의를 추가하고, 계약·바인딩·질의·컴파일러·솔버 버전 및
  검사 범위를 함께 저장해야 한다. 기본 일관성 검사만으로 장면별 검증 완료를 표시하지 않는다.
- SAT는 영상 해석, 제약 선택의 사실성, 실제 차량 안전성을 증명하지 않는다.

### GS-05 자연어·저장·수정

- 승인 계약에서 자연어를 생성하고 renderer 버전·조항 대응을 저장한다.
- 공용 action CNL renderer는 구조 검사만 수행하는 영어 단방향 투영이다. 렌더링 성공을
  SMT 통과로 간주하지 않고 동일 계약 버전의 승인·검사 결과를 따로 확인한다. 한글 CNL은
  지원 프로파일별 결정적 템플릿과 조항 대응을 확인한 뒤 제공한다. 같은 입력·renderer 버전은
  같은 CNL을 내야 하며 원문 계약이 실행 권위를 유지한다.
- 원본 CoC/승인 CoC/제약 CNL/결합 CoC를 보존한다. 기존 행동과 충돌하면 표시하고 재승인한다.
- 자연어 제약 수동 수정과 번역도 새 버전이며 의미 보존 승인을 다시 받는다.
  결정적 생성 원문과 수동 파생문을 구분하고, 파생문 승인이 기존 SMT 보증을 자동 이전하지 않는다.
- 서버 자동 임시 저장, 명시적인 시점별 완료 버튼, 오류 항목 이동과 실제 완료 수를 제공한다.
- 확대 복귀, 앞뒤 탐색, 새로고침, 서버 재시작으로 입력이 사라지면 안 된다.
- 해시는 추적 메타데이터에 보존하되 기본 검토 문장에서는 숨긴다.

### GS-06 학습 데이터 export

- JSONL: 영상/주행 ID, t0, 과거 프레임 참조·시간, 출처/라이선스, 원본/승인 CoC,
  제약/EBLC/CNL/결합 CoC, 행동 레이블·근거·미확인 마스크, 생성/승인/검증 버전과 split 그룹을 포함한다.
- 미확정/미승인/검증 보류는 초안 export로 분리한다. 적용 제약이 없음을 사람이 확인한 경우만
  NOT_APPLICABLE로 구분하여 baseline 자료로 보관하되 제약 강화 적격으로 세지 않는다.
  빈 제안 목록·미실행·거절·미지원은 그 자체로 NOT_APPLICABLE이 아니다.
- 주행/영상 단위로 split을 관리한다. 인접 프레임을 train/test 양쪽으로 나누지 않는다.
  동일 원본의 재업로드·재추출·겹치는 파생 클립과 baseline/강화본도 동일 그룹에 묶고
  train/validation/test 사이 중복을 차단한다. 원본 계보가 불명확하면 split 확정을 보류한다.
- t0 이후 영상은 입력에 넣지 않는다. 원문 CoC에도 미래 관찰이 섞이면 수정하거나 누출 표식으로 제외한다.
- CoC/CNL을 입력으로 쓰는 모드와 출력 학습 목표 모드를 export 설정으로 구분한다.
  행동 정답은 입력에서 제외하며 대응 baseline/강화본은 공통 영상·질문·행동 레이블을 유지한다.
- 독립성이 확인되지 않은 승인 자료는 개발/학습용이다. 독립 평가 정답과 구분한다.
- 완료된 기존 run/원답을 덮어쓰지 않고 새 export 버전을 만든다.
- export는 저장 완료된 단일 버전 스냅샷을 사용한다. CoC·제약·관찰 바인딩·검사·CNL·결합 CoC·
  행동 승인 중 버전이 어긋난 항목은 학습용에서 제외하고 제외 사유와 수를 보고한다.

## 4. 상태와 보안

시점별 독립 ID/버전을 갖고 CoC, 제약, 명세 검사, CNL, 행동 레이블, export 적격 상태를 분리한다.
상위 수정 시 의존 결과만 STALE로 만들고 과거 승인은 보존한다. 비동기 결과를 입력 버전에 묶어
늦게 도착한 응답이 최신 수정본을 덮어쓰지 않게 한다. 동시 편집은 버전 충돌을 처리한다.
자동저장도 영상/추출 설정/시점 ID와 기준 revision에 묶고, 화면 이동 뒤 도착한 저장 응답을
다른 시점에 적용하지 않는다. 저장 중·완료·실패를 구분하며 서버 확인 전 완료로 표시하지 않는다.
출처·관찰·영역·추출 설정 변경도 관련 승인과 검사에 전파한다. 이전 시점 상태를 참조하는 경우
그 의존 버전을 기록하고, 재검토 중 뒤 시점의 정보를 앞 시점 입력에 역으로 전파하지 않는다.
검토자 신원·승인 시각을 생성 모델이 만들어내지 않는다.

기본 local/loopback 서비스와 인증된 쓰기를 사용한다. 업로드 경로 이탈, 임의 파일 읽기,
원문 HTML 실행을 차단한다. 제한 영상은 RESTRICTED에 저장하고 외부 모델 전송은 별도 승인한다.
자격증명은 브라우저/로그/export에 넣지 않는다. 영상/CoC 내용은 실행 지시가 아닌 데이터다.
모델·업로드·솔버 작업에 크기/시간 제한, 오류 재시도·취소와 중복 방지를 둔다.

## 5. 범위와 배치

- MVP 제외: 차량 제어, 궤적 정답 생성, RL, 실차 안전 인증, 범용 법규 추출, 본 학습 자동 실행.
- ego-motion은 추후 참조 연결만 고려한다. 영상만으로 실측 좌표를 만들지 않는다.
- 현재 학습 GPU/실험 프로토콜/논문 산출물/기존 검토 DB를 변경하지 않는다.
- 문서는 Project 04 표준 docs에 귀속한다. 웹앱 예정 경로는 `apps/guardsynth_studio/`이며
  코드 생성 전에 PROJECT_REGISTRY applications에 owner를 등록한다.
- 장면 적용성은 Project 04, 공용 파서/Core/SMT/CNL은 `platforms/eblc-bcv/`를 재사용한다.
- `apps/research_portal/`의 저장·보안을 검토 후 재사용한다. 운영 포털을 바로 대체하지 않는다.
- 실행 자료: `projects/04-guardsynth-coc/artifacts/restricted/guardsynth-studio-001/<run-id>/`.
- #18 전용 연결 코드는 범용 추출기가 아니다. 지원 범위는 실제 테스트로 확인한다.

기존 구현의 재사용 경계는 다음과 같다. 아래 파일은 참조 대상이며 이번 단계에서 변경하지 않는다.

- [포털 저장소](../../../../apps/research_portal/review_store.py)는 검토 회차·할당·불변 revision용이며,
  영상 업로드·시점별 CoC 자동저장 기능이 이미 구현된 것으로 간주하지 않는다.
- [proposal 스키마](../../src/guard_synth/schemas/constraint_proposal_bundle.schema.json)는
  제안 및 근거 참조의 출발점이며 Studio 승인 이력·저장 스키마를 대신하지 않는다.
- [action-contract](../../../../platforms/eblc-bcv/src/guard_synth_eblc/action_contract.py)와
  [공용 CNL](../../../../platforms/eblc-bcv/src/guard_synth_eblc/cnl_renderer.py)은 제한된 계약 경로다.
- [scene18 연결](../../src/guard_synth/qualitative_scene_contract.py)은 특정 clip·시점·대상에 고정되어 있다.
  [장면 CNL](../../src/guard_synth/scene_conditioned_cnl.py)은 보행자 충돌·주도로 양보 두 술어와
  단일 관찰 시점에 한정되며 `learning_export_allowed=False`를 반환한다. 이 결과나 기존 검토를
  Studio의 범용 추출·학습 승인으로 승격하지 않는다.
