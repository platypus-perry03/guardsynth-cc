# GuardSynth Studio 검증 성질 정형 명세

- 소유 프로젝트: `guardsynth-coc`
- 기준일: 2026-10-04
- 상태: 기존 검증과 추가 후보를 통합한 설계 명세
- 검증 단위: 바로 이전 장면과 현재 장면 및 이전 장면이 전달한 유한 상태 요약
- 구현 기준: [장면 검증 모듈](../../src/guard_synth/studio_grounded_sequence.py), [추가 성질 실험](../../experiments/studio_property_probe.py)
- 관련 설계: [연속 CoC 설계](STUDIO_SEQUENTIAL_COC_DESIGN_V01.md), [EBLC 도식 설계](STUDIO_EBLC_DIAGRAM_DESIGN_V01.md)

이 명세는 생성된 CoC와 제약의 관찰 근거, 논리적 일치, 조건의 지속과 해제, 행동의 선행 및 후행 조건을 기술한다. 앞서 논의한 추가 성질 1–4는 A1–A4로 유지한다. 각 성질의 정형적 정의와 현재 구현 여부를 구분하며, 명세를 작성한 사실이 구현 완료나 실제 오류 검출 효과를 의미하지 않는다.

검증 통과는 주어진 입력과 명세 안에서의 판정이다. 영상 해석의 진실성, 사고가 발생하지 않은 원인, 행동의 유일한 정당성 또는 실제 주행 안전성을 증명하지 않는다. 특히 CoC와 제약을 같은 VLM이 만들면 두 출력이 함께 잘못되어도 내부 일치 검사를 통과할 수 있다.

## 입력과 기호

검증 창은 다음과 같다.

```text
W_t = (X_{t-1}, X_t, Σ_{t-1})
X_i = (CoC_i, Constraints_i, Evidence_i, timestamp_i)
Σ_i = (조건 정의와 버전, 유지 의무, 대상 대응, 직전 행동, 근거 참조, 공백 표시)
```

전체 과거 영상과 문장을 매번 SMT에 넣지 않는다. 과거에서 이어지는 의무는 바로 이전 요약에 포함한다. 첫 장면에서 이전 요약이 없으면 이전 이력을 검증하지 못한 시작점으로 표시한다. 관찰 공백이 있으면 공백을 표시하고, 공백 동안 조건이 충족되었다고 추정하지 않는다.

행동은 종류만으로 비교하지 않고 다음과 같이 구체화한다.

```text
a = (code, actor, target, movement, interval)
code ∈ {START, STOP, CONTINUE, ENTER, HOLD}
Match(d,a) = 행위자·행동 종류·대상·진행 방향·적용 시간 범위의 대응이 확인됨
```

`HOLD`는 이미 정지한 상태의 유지, `CONTINUE`는 주행 지속, `STOP`은 정지 동작이다. 정지 동작을 기록한 시점에 이미 속도가 0이어야 한다고 가정하지 않는다. `ENTER`와 `CONTINUE`는 함께 기록될 수 있다. 서로 다른 대상으로 향하는 진입을 같은 행동으로 합치지 않는다. 대상이나 방향이 미지정이면 자동으로 모든 대상에 적용하지 않고 해당 검사를 보류한다.

제약 정의는 다음 요소를 갖는다.

```text
d = (id, version, class, actor, condition_targets, action_target, movement,
     actions, effect, G_on, G_off, Pre, Post, scope, source)
effect ∈ {FORBID, REQUIRE, ALLOW}
G_on  = 활성 조건의 논리곱
G_off = 해제 조건의 논리합
Pre   = 행동 이전에 요구되는 조건의 논리곱
Post  = 행동 후 확인하려는 조건
```

`scope`, `interval`, 후행 조건의 완료 판정 범위, 설명과 조건을 연결하는 필드는 설계상 필요하며 현재 입력 형식에 모두 구현되어 있지는 않다. 현재 모듈은 주로 현재 시점과 행위자·대상·진행 방향의 정확한 대응을 사용한다.

7개 상위 클래스는 `TRAFFIC_CONTROL` 신호와 교통 통제, `VEHICLE` 차량, `VULNERABLE_ROAD_USER` 보행자와 자전거 등, `ROAD_LAYOUT` 도로 형상, `WORKZONE_OBSTACLE` 공사와 장애물, `ROAD_SURFACE` 노면, `VISIBILITY` 시야이다. 클래스는 조건의 원인을 정리한다. 같은 클래스라는 이유로 서로 다른 신호나 차량의 조건을 이어받지 않으며, 매 장면에 7개 클래스 모두가 있어야 하는 것도 아니다.

## 관찰값과 판정

각 원자의 관찰값은 `TRUE`, `FALSE`, `UNKNOWN`, `CONFLICT`이다. `UNKNOWN`은 참과 거짓 중 어느 쪽도 확인되지 않았다는 뜻이다. 동일한 대상·시점·좌표 기준의 원자에 참과 거짓이 함께 주어지면 `CONFLICT`이다. 과거의 관찰값을 현재의 관찰값으로 복사하지 않는다.

```text
F_t(p) = TRUE     → p_t를 주장
F_t(p) = FALSE    → ¬p_t를 주장
F_t(p) = UNKNOWN  → p_t를 참이나 거짓으로 고정하지 않음
F_t(p) = CONFLICT → 입력 충돌을 보고하고 이를 전제로 다른 성질을 증명하지 않음
```

`E_t`는 허용된 관찰 사실, 대상 대응, 시간 정보, 검토된 관계 의미를 결합한 근거 모델이다. 검사하려는 주장 자체를 근거 모델에 넣어 그 주장을 증명하지 않는다. 규범적 제약은 `K_t`, 실제로 관찰된 행동은 `O_t`로 구분한다.

각 성질은 대상 대응, 적용 범위, 필요한 입력이 갖추어졌을 때 검사한다. 입력 형식이 없으면 `NOT_CHECKED`, 적용 대상이 아니면 `NOT_APPLICABLE`이다. 해당 행동이나 활성 조건의 성립 자체가 미확인이면 그 조건부 성질을 공허하게 통과시키지 않는다.

일관된 근거 모델에 대해 주장 `φ`의 판정은 다음과 같다.

```text
SAT(E_t) = UNSAT                          → INPUT_CONFLICT
SAT(E_t ∧ ¬φ) = UNSAT                     → SUPPORTED
SAT(E_t ∧  φ) = UNSAT                     → CONTRADICTED
SAT(E_t ∧  φ) = SAT, SAT(E_t ∧ ¬φ) = SAT  → UNCONFIRMED
시간 초과 또는 솔버 UNKNOWN               → SOLVER_UNKNOWN
```

`E_t ∧ ¬φ`의 만족 가능한 모델 하나만 발견한 경우, 미확인 입력에서는 가능한 반례이지 실제로 발생한 오류가 아니다. 명확한 불일치는 근거가 반대 결론을 지지할 때 판정한다. 반대로 규칙들의 양립 가능성을 검사할 때는 `SAT(E_t ∧ K_t)` 자체를 검사한다. 만족 가능성과 논리적 함의의 구분 및 부정식을 이용한 함의 검사는 [Z3 공식 설명](https://microsoft.github.io/z3guide/docs/logic/propositional-logic/)에 따른다.

검사 결과는 논리 판정과 근거 검토 상태를 별도 저장한다. 근거 미확인을 모순으로 세지 않으며, 일부 성질만 검사했는데 전체가 통과했다고 표시하지 않는다.

## 기존 검증 성질

### B1 대상과 관계의 형식 적합성

```text
∀ p ∈ 사용 원자:
  Bound(subject(p)) ∧ Bound(object(p), 해당 시)
  ∧ TypeCompatible(p) ∧ IdentityResolved(p)
∀ a ∈ 사용 행동: ActorBound(a) ∧ TargetCompatible(a)
```

예를 들어 `SIGNAL_GREEN`의 대상은 신호기이며, `PATH_CLEAR(zone)`은 특정 영역이나 차로에 관한 조건이다. 자차만 지정한 경로 여유 조건으로 특정 교차로의 진입을 정당화할 수 없다. 객체 대응이 불확실하면 관련 원자를 미확인으로 다루고 다른 차량의 의무를 잘못 이어받지 않는다.

현재 구현은 종류와 참조 검사 및 불확실한 객체 대응의 처리를 제공한다. 실제 객체의 동일성은 입력한 대응의 품질에 의존한다.

### B2 근거의 시간과 적용 대상 적합성

```text
Accepted(p_t) ⇒ EvidenceLinked(p_t)
                 ∧ SupportsPredicate(evidence,p_t)
                 ∧ MatchesScope(evidence,p_t)
AcceptedReason(e,a) ⇒ AvailableBeforeDecision(e,a)
```

현재 상태에 대한 주장은 현재 관찰 또는 명시적으로 허용한 유효 기간의 근거를 사용한다. 미래 영상으로 과거 판단 당시의 이유를 뒷받침하지 않는다. 결과를 확인하는 후행 검사는 행동 뒤의 근거를 사용할 수 있으나 이를 당시의 판단 근거로 되돌려 쓰지 않는다. 시간 범위가 겹쳐 선후 관계를 확정할 수 없으면 보류한다.

현재 구현은 현재 근거 ID와 원자의 근거 종류를 검사하며 `STOPPED`에 CAN 참조를 허용한다. 세부 의사결정 시각, 관찰 유효 기간, 문장별 인과 시각 검사는 부분 구현이다. 근거 ID 연결이 영상 의미의 정확성을 입증하지는 않는다.

### B3 관찰과 공간 관계의 일관성

```text
SAT(F_t ∧ R_t)
LEFT_OF(x,y,t) ↔ RIGHT_OF(y,x,t)
¬(LEFT_OF(x,y,t) ∧ LEFT_OF(y,x,t))
LEFT_OF(x,y,t) ∧ LEFT_OF(y,z,t) ⇒ LEFT_OF(x,z,t)
```

`R_t`는 같은 좌표 기준에서 해석하는 관계의 의미이다. 전후 관계도 같은 방식으로 검사한다. 순환하는 엄격 순서는 허용하지 않는다. 다른 시점이나 서로 다른 좌표 기준의 좌우 관계를 같은 사실로 비교하지 않는다.

현재 구현은 현재 시점의 정수 순서 축으로 역관계, 반대 방향 및 순환 모순을 검출한다. 명시적인 좌표 기준 필드는 없으므로 입력이 같은 기준을 사용한다는 전제가 필요하다. 관찰 원자 자체의 충돌과 관계 의미를 적용한 충돌은 원인을 구분해 보여준다.

### B4 조건 정의의 동일성

```text
Same(id,version,d_{t-1},d_t) ⇒ Def(d_{t-1}) = Def(d_t)
DefinitionChanged(d) ⇒ 새 버전 또는 새 ID와 변경 기록 필요
```

신호나 차량의 현재 상태는 갱신할 수 있지만 동일한 조건 ID가 나타내는 대상·효과·활성 및 해제 의미를 조용히 바꾸지 않는다. 현재 구현은 같은 ID의 정의를 구조적으로 비교하며 변경을 충돌로 보고한다. 명시적인 정의 버전 전환은 추가 설계 사항이다.

### B5 조건 유지와 해제의 연속성

```text
ConfirmedOn(d,t)  := E_t ⊨ G_on(d,t)
ConfirmedOff(d,t) := E_t ⊨ G_off(d,t)

Active(d,t-1) ∧ ¬ConfirmedOff(d,t) ⇒ RetainObligation(d,t)
ConfirmedOff(d,t) ⇒ Released(d,t)
ConfirmedOn(d,t) ∧ ¬ConfirmedOff(d,t) ⇒ Active(d,t)
Active(d,t) ⇒ RetainObligation(d,t)
```

`¬ConfirmedOff`는 해제가 확인되지 않았다는 뜻이며 `E_t ⊨ ¬G_off`와 다르다. 이전에 유지 중이던 의무는 해제가 미확인이라고 삭제하지 않는다. 의무를 유지한다는 것이 장애물이 물리적으로 계속 존재한다고 관찰했다는 뜻은 아니다. 현재 입력에 이전 조건이 빠져도 이전 요약에서 그 의무를 이어받는다.

활성과 해제가 동시에 확인되면 별도 검토된 우선 의미가 없는 한 `LIFECYCLE_CONFLICT`이다. 이 경우 앞의 갱신식으로 활성과 해제를 동시에 확정하지 않는다. 처음부터 활성 여부가 미확인이었던 조건은 활성으로 만들어내지 않는다. 오래된 허용 조건으로 현재 행동의 허용을 확정하지 않으며, 허용의 현재 근거는 A3에서 다시 검사한다.

현재 구현은 유한한 조건 원장과 활성·해제 상태를 이어받는다. 의무를 삭제하지 않는 대신 해제 미확인 상태를 표시한다. 전체 이력이 요약에 정확히 반영되었는지는 별도의 입력 관리 책임이다.

### B6 활성 제약의 양립 가능성과 기록 행동의 적합성

```text
Active(d,t) ∧ Match(d,a) ∧ effect(d)=FORBID  ⇒ ¬Occurs(a,t)
Active(d,t) ∧ Match(d,a) ∧ effect(d)=REQUIRE ⇒  Occurs(a,t)
ALLOW(d,a,t) ⇏ Occurs(a,t)

SAT(E_t ∧ T_t ∧ K_t)       : 활성 제약들이 양립 가능한가
SAT(E_t ∧ T_t ∧ K_t ∧ O_t) : 기록 행동이 그 제약과 양립 가능한가
```

`T_t`는 B5의 상태 전이이다. 같은 범위에서 행동을 요구하면서 금지하면 제약 간 모순이다. 일관된 제약이 금지한 행동을 실제로 기록했으면 행동과 제약의 모순이다. 조건부 허용 후보와 금지가 함께 있다고 바로 규칙 간 모순으로 판정하지 않는다.

`REQUIRE`는 해당 시점 또는 정해진 구간 안에 수행할 의무이다. 완료 기한이 아직 도래하지 않았는데 행동이 없다는 이유로 위반이라 하지 않는다. 행동 목록이 비어 있으면 `O_t`는 미확인이며, 관찰의 완전성이 확인되어 있거나 명시적인 부정 관찰이 있을 때만 행동하지 않았다고 고정한다.

현재 구현은 활성 `FORBID` 및 `REQUIRE`와 행동의 대조를 제공하고 `ALLOW`를 실행 의무로 강제하지 않는다. 다만 현재 SMT 행동 쿼리는 목록에 없는 행동을 거짓으로 설정한다. 관찰 누락과 실제 미수행을 구분하는 본 명세의 원칙은 아직 완전히 반영되지 않았다. 시간 구간을 갖는 수행 의무도 추가 모델링이 필요하다.

### B7 행동 선행 조건의 충족

```text
Applies(d,a,t) ∧ Observed(a,t) ∧ PreconditionsRequired(d,a)
  ⇒ E_t ⊨ Pre(d,a,t)
```

특정 행동에 적용되는 선행 조건이 확인된 거짓이면 불일치이고, 미확인이면 추가 확인이다. `Applies`에는 활성 여부와 B1의 대상 대응이 포함된다. 선택되지 않은 다른 허용 후보의 선행 조건까지 모든 행동에 강제하지 않는다. 선행 조건의 목록 자체가 충분한지는 A2에서 따로 검사한다.

현재 구현은 활성 제약의 선행 조건과 대응하는 기록 행동을 검사한다. 어떤 조건이 해당 행동에 필수인지에 관한 의미는 정의 입력에 의존한다.

### B8 행동 후 기대 결과의 적합성

```text
Observed(a,t-1) ∧ PostBinding(d,a)
  ∧ OutcomeWindowClosed(d,a,t) ∧ SameTarget(d,a,t)
  ⇒ E_t ⊨ Post(d,a,t)
```

행동에 연결된 결과이고 그 결과를 확인할 시간이 지났을 때 검사한다. 허용되었다는 이유만으로 행동 수행이나 완료를 요구하지 않는다. ‘정지 동작을 시작했다’와 ‘정지가 완료되었다’를 구분한다. 결과가 관찰되지 않으면 미확인이며, 명확한 반대 관찰이 있을 때 불일치로 판정한다. 제약의 해제와 행동 완료도 구분한다.

현재 구현은 이전 행동에 연결된 기대 결과를 현재 장면과 대조한다. 명시적인 완료 기한이나 결과 확인 구간을 입력하는 기능은 없다. 따라서 모든 기대 결과가 바로 다음 썸네일에서 성립해야 한다는 의미로 확장하면 안 되며, 현재 검사는 다음 장면에서 평가 가능한 결과로 한정해야 한다.

### A2 장면과 행동에 필요한 조건의 누락

### A3 개별 허용 후보와 전체 행동 허용의 구분

```text
Permit(a,t) ⇏ REQUIRE(a,t)
```

### A4 관찰 행동과 CAN 측정의 일치

```text
EligibleCAN(q,t) = Linked(q,t) ∧ UnitsValid(q) ∧ QualityAccepted(q)
                   ∧ 0 ≤ timestamp_t − timestamp_q ≤ δ
                   ∧ LatestPastSample(q,t) ∧ speed(q) ≥ 0

EligibleCAN(q,t) ∧ DecidableMotion(q) ∧ HOLD(ego,t)     ⇒ speed(q) ≤ ε_stop
EligibleCAN(q,t) ∧ DecidableMotion(q) ∧ CONTINUE(ego,t) ⇒ speed(q) ≥ ε_move
ε_stop < ε_move
```

두 경계 사이의 속도는 레이블 판정을 보류한다. 실험은 `ε_stop=0.5 km/h`, `ε_move=2.0 km/h`, `δ=0.6 s`를 사용했다. 이 값은 평가 프로토콜의 선택이며 모든 차량에서 검증된 기준이 아니다. 측정과 영상 사이의 시간 차를 허용했다는 것은 그 사이 차량 상태가 같았다는 증명이 아니므로 결과는 연결된 측정값과 레이블의 일치로 표시한다.

`START`와 `STOP`에는 상태 전환을 판정할 시간 구간과 충분한 연속 측정이 필요하다. 정지 후 이동의 관찰은 출발의 경계를, 이동 후 정지의 관찰은 정지 완료의 경계를 평가하는 데 사용할 수 있다. 두 썸네일의 속도만으로 그 사이의 모든 전환을 배제하지 않는다. `ENTER`의 대상 영역 진입은 속도만으로 판단할 수 없다.

## 결과 관리와 추적성

### O1 검증 결과의 최신성


### O2 논리 판정과 규칙 출처의 분리

```text
SourceReviewed(d) = 원문 연결 ∧ 해당 규칙의 검토 상태 확인
LogicalConsistency(d) ⇏ SourceReviewed(d)
SourceReviewed(d) ⇏ 실제 행동의 적법성 또는 안전성
```

규칙 출처가 없는 관찰 기반 제약 후보는 후보로 표시한다. 원문 연결의 부족을 SMT 모순으로 처리하지 않는다. 현재 구현도 규칙 출처 검토를 논리 검사와 분리한다.

각 불일치에는 장면, 성질 ID, 대상, 입력 경로, 실제 비교값, 근거 ID와 수정 대상을 연결한다. 충돌한 제약 집합에는 unsat core, 가능한 반례에는 해당 입력을 만족하는 모델을 붙인다. unsat core는 충돌 원인의 부분집합이며 반드시 최소 집합인 것은 아니다. 근거가 없으면 빈 배열 대신 ‘근거 미입력’과 필요한 항목을 표시한다. 같은 원인의 반복은 묶되 어떤 대상과 장면에 영향을 주는지 유지한다.

## 검증 자원과 평가 기준

## 앞서 논의했으나 우선 추가 대상에서 제외한 성질

같은 신호기의 같은 진행 방향에서 적색과 녹색이 동시에 주장되는 경우에는 다음 상호배타성을 사용할 수 있다. 다른 신호기, 다른 방향, 전환 시각의 불확실성을 먼저 분리해야 하며 현재 공간 관계 검사만으로 이 의미가 자동 구현되어 있지는 않다.

```text
SameSignalMovement(s,m,t) ⇒ ¬(RED(s,m,t) ∧ GREEN(s,m,t))
```

조건이 절대로 활성화될 수 없거나 의도한 해제 조건이 의미상 불가능한지 보는 비공허성 검사도 논의했다.

```text
SAT(Domain_d ∧ G_on(d))
SAT(Domain_d ∧ G_off(d))   : 해제가 가능해야 한다고 명세한 조건에 한정
```

이는 정의 수준의 도달 가능성 후보 검사이며, 현재 장면에서 활성 근거가 없다는 이유로 정의가 잘못되었다고 판단하는 검사가 아니다. 두 식이 만족 가능해도 실제 시간에 따라 활성에서 해제로 진행할 수 있다는 보장은 없다. 영구 제약의 해제까지 강제하지 않는다. 이번 우선 추가 범위 1–4에는 포함하지 않았다.
